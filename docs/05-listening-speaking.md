# 듣기 · 말하기 (2단계)

## 1. 콘텐츠

| 항목 | 목표 | 구현 | 비고 |
|---|---|---|---|
| A1 듣기 대화 | 10 | **10** | 6줄 대화, 스크립트·해석·핵심 단어 4·핵심 표현 2·문제 3 |
| 듣기 문제 | — | 30 | 이해도 객관식 20 + 받아쓰기 10, 모두 해설 포함 (100%) |
| 듣기 음성 제공률 | 100% | **100%** (60개 mp3) | 콘텐츠 테스트로 파일 존재·크기 검증 |
| A1 따라 말하기 문장 | 30 | **30** | 예시 음성 30개 mp3, 연결 문법·대화 표시 |
| A2~B2 듣기·말하기 | — | 준비 중 | 음성 미제작 레벨은 '준비 중'으로만 표시 |

대화·문장·해설은 직접 작성했습니다 (`src/data/listening.ts`, `src/data/speaking.ts`).

## 2. 음성 (합성 음성)

- 엔진: [Piper](https://github.com/rhasspy/piper) TTS, 모델 `en-us-libritts-high` (화자 4 = 여성, 6 = 남성).
- 모델 학습 데이터: LibriTTS (CC BY 4.0) → 상업적 이용 가능, **출처 표기 필요** (`public/audio/CREDITS.md`, 앱 MY 화면).
- 학습자용으로 조금 느리게(length_scale 1.3) 만들고 64kbps mono mp3로 변환. 총 90개, 약 1.9MB.
- 재생성: `npx vite-node scripts/audio-manifest.ts > manifest.json && python3 scripts/gen-audio.py manifest.json <모델.onnx> public`
- **원어민 녹음이 아닙니다.** 앱에 '합성 음성'으로 표시합니다. 발음·억양의 자연스러움은 사람이 직접 들어 보고 검수해야 합니다 (미완료).

## 3. 기능

| 기능 | 상태 |
|---|---|
| 레벨별 듣기 목록, 완료 표시·최근 점수 | 구현 |
| 대화 전체 재생 / 일시정지 / 이어서 / 처음부터 / 한 줄만 다시 듣기 | 구현 |
| 반복 듣기, 재생 속도 0.75·1·1.25x | 구현 |
| 스크립트 숨기기·보기, 한국어 해석 보기 | 구현 |
| 이해도 문제·받아쓰기 (문항마다 음성 버튼), 정답·해설 | 구현 |
| 듣기 오답 → 오답노트 + 대화 재청취 복습(`l:`) 등록 | 구현 |
| 받아쓰기 오답 → 핵심 표현이 담긴 대화를 다른 문제 유형으로 복습 | 구현 |
| 음성 재생 오류 안내 (파일 로드 실패·재생 거부) | 구현 |
| 예시 음성 듣기 | 구현 |
| 마이크 사용 동의 (동의 전 마이크 미사용, MY에서 철회) | 구현 |
| 녹음 시작·종료(최대 10초), 내 녹음 다시 듣기 | 구현 (MediaRecorder) |
| 음성 인식(STT) → 목표 문장과 단어 단위 비교 (누락·추가·다르게 인식) | 구현 (Web Speech API) |
| 다시 말하기, 말하기 기록 저장 | 구현 |
| 누락·다르게 인식된 단어가 있으면 따라 말하기 재연습 복습(`s:`) 등록 | 구현 |
| 권한 거부·마이크 없음·HTTPS 아님·STT 미지원 안내 | 구현 |
| 커리큘럼 연동: A1 DAY = 단어 → 문법 → 확인 문제 → **대화 듣기 → 듣기 문제 → 따라 말하기** → 영작 → 마무리 테스트 | 구현 |
| 단어별 발음 정확도·강세·억양·유창성·문장별 피드백·AI 코칭 | **준비 중** (인터페이스: `src/lib/voice/pronunciation.ts`) |

**인식 일치도 ≠ 발음 점수.** 앱은 STT 결과와 목표 문장의 단어 일치 비율만 '인식 일치도'로 보여 주고, 발음 정확도 점수는 만들지 않습니다. 실력분석에서도 말하기는 참고 지표로만 표시하고 실력 지도 점수에 넣지 않습니다.

## 4. 음성 데이터 처리 방침

- 녹음 버튼을 누를 때만 마이크를 켜고, 종료 버튼 또는 10초 후 마이크 트랙을 끕니다.
- 녹음 파일은 연습 화면 메모리에만 두고(다시 듣기용), 서버 전송·기기 저장을 하지 않습니다. 화면을 떠나면 사라집니다.
- 음성 인식은 브라우저 내장 기능입니다. Chrome·Edge는 인식을 위해 음성을 브라우저 회사 서버(Google·Microsoft)로 보낼 수 있습니다. 동의 화면과 MY에 안내합니다.
- 앱에 저장되는 것은 인식된 텍스트, 비교 결과(누락·추가·다르게 인식된 단어, 일치도), 시각뿐입니다.

## 5. 브라우저 지원 범위 (2026-11 기준)

| 환경 | 재생 | 녹음 | 음성 인식 | 확인 방법 |
|---|---|---|---|---|
| Chromium (Playwright, 가짜 마이크 장치) | ✅ 실제 mp3 재생 | ✅ 실제 MediaRecorder | ⚠️ 모의 인식기로 흐름만 검증 | 자동 테스트 |
| Chrome / Edge 데스크톱·Android | 예상 ✅ | 예상 ✅ | 예상 ✅ (서버 인식) | **실기기 테스트 필요** |
| Safari macOS / iOS 14.1+ | 예상 ✅ | 예상 ✅ | 예상 ✅ (webkitSpeechRecognition) | **실기기 테스트 필요** |
| Firefox | 예상 ✅ | 예상 ✅ | ❌ 미지원 → 녹음 자가 확인 모드 | 미지원 안내 동작은 자동 테스트로 확인 |

- 마이크는 보안 연결에서만 동작합니다. 테스트는 `http://localhost`(브라우저가 보안 연결로 취급)에서 했고, 배포 시 HTTPS 도메인에서 다시 확인해야 합니다.
- Android Chrome 일부 기기에서는 녹음과 음성 인식이 마이크를 동시에 쓰지 못할 수 있습니다. 이때 녹음은 실패해도 인식은 계속하도록 처리했지만, 실기기 확인이 필요합니다.
- Android·iOS 앱 전환(Capacitor) 시: WebView의 Web Speech API 지원이 제한적이라 네이티브 음성 인식 플러그인으로 바꿔야 합니다. `src/lib/voice/recognition.ts`의 `recognizeOnce()`만 교체하면 되도록 분리했습니다.
